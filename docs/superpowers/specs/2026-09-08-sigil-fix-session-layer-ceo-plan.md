## Problem

A sender and receiver in a Sigil conversation cannot tell whether messages were
lost, and cannot recover them. `docs/specs/sigil-v1-conformance-gap-closure-design.md`
section 10 shipped the sender-side half (delivery receipts + heartbeat, borrowed
from FIX) and explicitly parked the receiver-side half: FIX-style sequence-numbered
gap detection and resend (`MsgSeqNum` + `ResendRequest`). This plan builds that
parked work.

Reframed during CEO review: Sigil already has durable persistence, retry, and
dead-letter in `deliveries`, and `listInbox(since)` returns every queued delivery,
so a receiver that polls its inbox already gets a complete set. The real residual
gap is narrower: a receiver consuming the stream incrementally cannot distinguish
"nothing new yet" from "I missed a push," and there is no per-sender ordering.
The sequence number is the direct path to both.

## Approach (locked)

**Approach A — relay-assigned per-`(sender, conversation)` `stream_seq` + async resend.**

| Decision | Choice | Source |
|---|---|---|
| Sequence scope | Per-sender-per-conversation (one monotonic stream per sender within a conversation) | brainstorm |
| Gap handling | Detect-and-request, non-blocking (receiver keeps processing what it has) | brainstorm |
| Sequence authority | Relay-assigned at accept, outside the sender's envelope signature | brainstorm |
| NAK mechanism | New in-band `business.reject` envelope type | brainstorm — **split to Plan 2** |
| Federation | Single-relay only for Plan 1; federated `stream_seq` deferred | eng review A1 |
| Resend transport | Stays a signed envelope; fulfilment is async via a worker, off the hot accept transaction | eng review A2 |
| Job queue | Generalize `federation_outbox` + `federation-reaper` into a shared `relay_jobs` queue; do not build a parallel copy | eng review CQ1 |

Alternatives considered and rejected:
- **B — reconcile-only, no schema change** (connector treats `listInbox` as
  authoritative, polls harder). Smaller, but no true gap *detection* (cannot tell
  lost from delayed), no per-sender order, and dead-ends — nothing to build the
  federated and NAK legs on.
- **C — sender-assigned seq inside the signed envelope.** The right long-term
  shape (closes the federation integrity gap for free), but rejected in
  brainstorm: sender can gap or lie, relay must track expected-next per stream
  and reject out-of-order, and every connector must number its own stream.

## Accepted Plan 1 Scope

1. `stream_sequences` table + `envelopes.stream_seq` column (migration), stamped
   per `(sender_endpoint_id, conversation_id)` in the accept transaction via an
   `INSERT ... ON CONFLICT DO UPDATE ... RETURNING` counter. **Behind a relay
   config flag (default off).** Local conversations only — federated inbound
   envelopes leave `stream_seq` NULL.
2. `stream_seq` exposed on the inbox listing, the `delivery.receipt` push, and
   the `delivered` stream frame.
3. Generalize `federation_outbox` + `federation-reaper` into a shared `relay_jobs`
   queue (claim / retry / dead-letter) with a `job_type` discriminator.
   Sequenced as two commits: (a) refactor federation onto the shared queue with
   the existing federation tests still green, (b) add resend as a second
   `job_type`.
4. `session.resend_request` signed envelope (`begin_seq` / `end_seq`, range cap).
   The accept path validates and records it only; a `relay_jobs` worker does the
   `envelopes` lookup and stream re-push outside the transaction. Auth: requester
   must be an active `conversation_members` row. Counts against `quota_usage`.
5. Aged-out handling: any requested seq with no surviving `envelopes` row (past
   the 24h `expires_at`, or `expires_at <= now`) is reported as one
   `sequence_reset` control frame; the receiver advances its cursor and records
   the loss. No fabricated messages.
6. Connector `stream-gap-tracker.mjs` (one shared module, injected storage; CLI
   uses the `inbox-wait.mjs` ledger, adapters inject their host store):
   contiguous-advance, buffer + debounced `session.resend_request` on a gap,
   drop duplicates, honor `sequence_reset`, reload high-water mark on restart,
   and on permanent failure deliver held messages with an unrecoverable-gap
   event (#3).
7. CLI: `sigil inbox` (now contiguous-ordered per stream), `sigil inbox --gaps`,
   `sigil resend --conversation C --from N --to M --sender ep_X`.
8. Observability (#1): counters, resend-latency histogram, structured log lines,
   dashboard panel spec.
9. Tests: the 13 coverage gaps from the eng review, plus the
   **CRITICAL regression** — the federation drain must stay green after the
   `relay_jobs` refactor.

## Reversibility

- `stream_sequences` table + `stream_seq` column: additive, flag-gated — ~4/5
  reversible (drop column, remove flag).
- `federation_outbox` -> `relay_jobs` refactor: ~3/5 — once federation rides the
  generalized queue it will not be reverted. Deliberate.

## Failure modes registry (from eng review)

| Codepath | Failure mode | Rescued? | Test? | User sees | Logged? |
|---|---|---|---|---|---|
| Seq upsert under concurrent same-stream accepts | deadlock (40P01) | retry on 40P01 (to spec) | gap → add | accept latency / 500 | yes |
| `relay_jobs` refactor breaks federation drain | silent stall | existing federation paths | **CRITICAL regression — add** | federated messages stall | yes |
| Resend fulfilment to a disconnected receiver | job first-miss | re-queue not dead-letter (to spec) | gap → add | stays gapped until reconnect | yes |
| Connector restart loses gap cursor | re-request storm | ledger reload mandatory | gap → add | resend flood, quota burn | yes |
| `sequence_reset` for a range that still exists (relay bug) | silent message skip | single-relay trust (A1); audit event on every `sequence_reset` | partial | silent loss | audit only |
| Resend range-cap bypass | oversized fan-out | `INVALID_ENVELOPE` | gap → add | rejection | yes |
| Gap never fills (resend exhausted / buffer overflow) | app blind or blocked | **release out-of-order + unrecoverable-gap event (#3)** | add | explicit gap marker | yes |

One critical gap: the federation-drain regression — no test yet, silent failure
mode. Must land with commit (a) of the `relay_jobs` refactor.
